Licence of contributions

Spagitty is GPL-3.0-or-later. By contributing you agree that your contribution is licensed under GPL-3.0-or-later. There is no CLA and no copyright assignment — you keep the copyright to your work.

Every new source file gets an SPDX header as its first line:

// SPDX-License-Identifier: GPL-3.0-or-later      <!-- Rust, TypeScript -->
<!-- SPDX-License-Identifier: GPL-3.0-or-later -->  <!-- Svelte, Markdown -->

Developer Certificate of Origin

We use the DCO rather than a CLA. Sign off every commit: 

git commit -s

That appends Signed-off-by: Your Name <you@example.com>. The name and email must be real and must match the commit author.

Branch and commit

  • Every branch carries a work item id from agile/: feature/FEAT-###-…, task/TASK-###-…, bugfix/BUG-###-…. If your change does not have an item yet, open one — it is a short document, and it is what makes the record readable a year later.
  • A pull request is the only path into main or dev.
  • A changelog entry goes under ## [Unreleased] in the same change as the work. Gate 6 reads that file for release notes and refuses to release without a section.
  • Update the documentation your change affects, in the same commit. A section describing something that no longer exists is a defect.

Before you push

cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
bun run check
bun run coverage

The full local gate sequence, including licences and advisories, is on CI/CD & releases.

Dependencies

Check the licence before adding one. Acceptable: MIT, Apache-2.0, BSD, ISC, MPL-2.0, LGPL, GPL-2.0-with-linking-exception, CC0, OFL (fonts). Not acceptable: proprietary, SSPL, BSL, or any “source available” non-free licence. Apache-2.0-only code must not be linked into GPL-2.0-only code.

A new dependency has to show up in the generated third-party licence list, and it has to be justified in the change that adds it.

Design rules that are not negotiable

These come from the design handoff and hold across every screen.

  • Standard git terminology only. fetch, push, stage, hunk, stash@{n}, pick/squash/reword/drop, ours/theirs. No invented vocabulary, no friendly renaming of git concepts.
  • Structural numbers are shared constants, never literals. The commit row pitch, the rail width, the detail panel width and the lane pitch each have exactly one definition. If you find yourself typing 26, use the constant.
  • Never block on walking the whole history. The graph streams in windows and paints progressively.
  • Destructive actions are reversible. Rebase previews before executing; conflict resolution writes nothing until finished; Undo maps to a reflog restore.
  • Nothing leaves the machine. Repositories are read straight from disk; credentials go in the OS keychain.
  • Never use the Git logo or Git orange. See brand & identity.

Code style

  • Rust: cargo fmt and cargo clippy clean.
  • Frontend: bun run check clean.
  • Do not reimplement what shell.rs should shell out to git for — interactive rebase execution, hooks, LFS, submodule recursion, credential helpers. If you need a new one of those, add it there with a comment explaining why gix is not the right tool, and extend the boundary table in the same change.
  • Do not reformat files you are not otherwise changing. A diff that is 90% whitespace is a diff nobody can review.
  • Write the why in the module header. A comment restating the signature is noise; the reasoning behind a choice is the thing that cannot be recovered from the code.

Reporting a bug

Useful reports say:

  • Which screen, by its code if you know it (1A, 1H, …).
  • Your platform and Spagitty version — Settings → License has both, along with the exact commit the build came from.
  • What you did, what happened, and what you expected instead.
  • If it involves a git operation, what Show the git command behind each action recorded. That drawer shows the actual argv, not a reconstruction.

For a suspected vulnerability, describe the class of problem rather than posting a working exploit.
