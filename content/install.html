Install & first run

Spagitty ships installers for Linux, macOS and Windows on every publishing merge. There is no account step and no cloud to log into — install it, open a repository, and work.

Download a build

Every release carries installers for all three platforms, built by the release lane rather than by hand:

Latest release All releases
PlatformWhat you getNotes
Linux .deb, .rpm and .AppImage Needs the platform WebView, WebKitGTK. Most desktop distributions already have it.
macOS .dmg and .app Apple silicon on the published release. The draft lane also builds an Intel binary.
Windows .msi and .exe installer Uses the system WebView2 runtime.
Nothing is signed yet

There is no Apple Developer account and no code-signing certificate in this project, so macOS Gatekeeper refuses a downloaded build on a double-click and Windows SmartScreen warns about it. On macOS, open it once from the context menu — right-click the app, choose Open, then Open again in the dialog. On Windows, choose More info → Run anyway. Adding real signing is a change to the build gate and the draft lane together, and it is tracked rather than quietly deferred.

First run

  1. Open a repository. The tab strip's +, the toolbar's repository picker, or the All repositories screen all do it. Spagitty never goes looking for repositories on its own — opening one is the only way it joins the list.
  2. The graph paints as it walks. Rows arrive in batches from a worker thread and never move once drawn, so a large repository is readable long before the walk finishes.
  3. Set your identity, if you want to. Settings → You reads user.name and user.email per scope and says which file each value came from. Saved profiles let you switch between them from the status strip.
  4. Connect a forge, if you use one. Settings → You → Accounts takes a personal access token for GitHub, GitLab or Bitbucket Cloud. The token goes into the OS keychain and never into a configuration file.
  5. Pick a theme. Settings → Appearance has eight palette families, each in light and dark. See themes & appearance.
Two things worth learning early

Ctrl/Cmd+P opens the command palette — everything Spagitty can do, filtered as you type. Ctrl+F goes straight to log search from any screen, with the first field focused.

Build from source

You need Rust 1.77 or newer, Bun 1.4, and the platform WebView.

git clone https://github.com/spa-git-ty/spagitty.git
cd spagitty
bun install

bun run check          # typecheck: svelte-kit sync && svelte-check
bun run test           # vitest
bun run coverage       # vitest with the coverage floor enforced
cargo test --workspace # the Rust suites

bun run tauri dev      # the desktop app, in development
bun run tauri build    # installers for this platform

On Linux you also need the WebKitGTK development packages that Tauri links against. The Tauri prerequisites list them per distribution; nothing in Spagitty adds to that list.

Opening a repository straight from the command line

The binary takes a path and opens onto it with no dialog. In development the argument has to be passed through both wrappers: 

bun run tauri dev -- -- -- /path/to/repository

That path is read by the launch_path command, which is also what the session restore falls back to when no path is given — see the launch sequence.

If the window comes up blank on Linux

WebKitGTK's DMABuf renderer cannot allocate a GBM buffer on some driver and compositor combinations, and a webview with no frame to present is a white window for the whole session. The symptom is a blank window with Failed to create GBM buffer on stderr. The workaround is one environment variable, and it is opt-in rather than forced on every Linux host: 

WEBKIT_DISABLE_DMABUF_RENDERER=1 spagitty

Spagitty sets WEBKIT_FORCE_COMPOSITING_MODE=1 for itself unless your environment already has an opinion, and deliberately sets nothing for the DMABuf renderer — turning it off for everybody costs every host the GPU path, which is a frame that lags the pointer during a resize. The reasoning is in the Tauri layer.

Running the gates locally

Gates 1 to 3 are what a change is checked against before it is committed. The full list, and what each one proves, is on CI/CD & releases. 

bun install --frozen-lockfile              # the dependencies, locked
cargo deny check licenses bans sources     # gate 1 — needs cargo-deny
cargo fmt --all --check                    # gate 2
cargo clippy --workspace --all-targets -- -D warnings
bun run check
python3 tools/make-icons.py --check        # gate 2 — brand drift, needs Pillow
python3 tools/make-brand.py --check
cargo llvm-cov --workspace \
  --ignore-filename-regex '(fixture|testing)\.rs' --summary-only
bun run coverage                           # gate 3
cargo deny check advisories                # gate 4
bun audit --audit-level=high

cargo-deny and cargo-llvm-cov install with:

cargo install cargo-deny cargo-llvm-cov

Updating

Settings → About checks whether there is a newer Spagitty than the one you are running. It is a check, not an updater: it tells you a version exists and where to get it, and nothing downloads or replaces anything behind your back.
