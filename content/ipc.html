How it is built

IPC reference

Every Tauri command and every event that crosses between the webview and the backend. All of them are reached from exactly one module on the frontend — src/lib/api.ts, plus src/lib/farm/api.ts for the farm — so a rename here is a one-file change there.

Conventions

Types crossing the boundary derive Serialize with #[serde(rename_all = "camelCase")] and are mirrored by hand in src/lib/types.ts. Errors cross as plain strings — Error's Display text is user-facing, and screens show it directly rather than substituting a message of their own.

The session and the walk

CommandDoes
open_repoOpens a repository, builds the ref index, computes the cheap counts, spawns a graph worker and a watcher. Returns { info, counts, token }.
close_repoTears down the walk and the watcher.
graph_requestAsks the worker for the next n rows. The worker walks nothing until asked.
graph_restartStarts a fresh walk. The old one's rows are dropped by token rather than cancelled.
graph_visibilityHide, solo, smart visibility and pin-to-left — resolved to a root set for a fresh walk, never a client-side filter.
snapshotThe repository's current state in one read: HEAD, counts, freshness.
metricsThe Rust side's structural constants, fetched at boot so the two copies of the row pitch can be compared.
launch_pathThe path the binary was started with, if any.

Events

EventCarries
graph-rowsA batch of commit rows, stamped with its walk's token. Rows carrying a stale token are dropped.
graph-doneThe walk reached the end.
search-rowsMatches, as the filtered walk finds them, with a query token.
search-doneThat query finished.
clone-progressGit's own progress, parsed. An unrecognised line is still shown.
clone-doneThe outcome, including a failure's message read from stderr.
network-progress · network-doneA fetch or push while it runs, and its result.
rebase-progress · rebase-doneRead from git's state counters rather than parsed from output.
repo-changedThe watcher saw something. Refs moving debounces into a re-read and a re-walk; a worktree change re-reads the counts only.
git-commandOne execution as shell.rs recorded it — argv, outcome, exit code, duration, with any URL userinfo already stripped.
farm-eventOne FarmEvent, internally tagged and timestamped. Sixteen variants on one channel, because the screen keeps one activity list and one ordering.

The FarmEvent variants

FarmStatusChanged, TaskCreated, TaskStatusChanged, TaskAssigned, TaskProposed, AgentStarted, AgentOutput, AgentStopped, VerificationStarted, VerificationFinished, ReviewRequested, ReviewCompleted, MergeRequested, MergeCompleted, WorkspaceChanged, Failed.
