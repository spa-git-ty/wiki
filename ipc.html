How it is built

IPC reference

Every Tauri command and every event that crosses between the webview and the backend. All of them are reached from exactly one module on the frontend — src/lib/api.ts, plus src/lib/farm/api.ts for the farm — so a rename here is a one-file change there.

Conventions

Types crossing the boundary derive Serialize with #[serde(rename_all = "camelCase")] and are mirrored by hand in src/lib/types.ts. Errors cross as plain strings — Error's Display text is user-facing, and screens show it directly rather than substituting a message of their own.

The session and the walk#

CommandDoes
open_repoOpens a repository, builds the ref index, computes the cheap counts, spawns a graph worker and a watcher. Returns { info, counts, token }.
close_repoTears down the walk and the watcher.
graph_requestAsks the worker for the next n rows. The worker walks nothing until asked.
graph_restartStarts a fresh walk. The old one's rows are dropped by token rather than cancelled.
graph_visibilityHide, solo, smart visibility and pin-to-left — resolved to a root set for a fresh walk, never a client-side filter.
snapshotThe repository's current state in one read: HEAD, counts, freshness.
metricsThe Rust side's structural constants, fetched at boot so the two copies of the row pitch can be compared.
launch_pathThe path the binary was started with, if any.

Reading#

CommandDoes
commit_detailThe message and the people for one commit.
commit_diffA commit's file list and totals — step one of the Diff screen's two-step load.
file_diffOne file's hunks, fetched as it is selected and cached by path.
binary_file_diffA size delta and a MIME type, for a file that has no lines.
working_copyThe status walk: staged, unstaged, untracked.
working_diff · binary_working_diffThe same two, for uncommitted work.
head_messageThe current HEAD's message — what an amend starts from.
branchesEvery branch with its drift, upstream and merged state.
stashesThe stash list, read from refs/stash's reflog.
blameLine attribution for a file. The one read that goes through the git binary.
file_historyA file's commits, following renames.
conflicts · conflict_sides · conflict_regionsWhat is conflicted, the three index stages of one path, and the marker regions inside it.
reflog · reflog_refsWhere a ref has been, and which refs have a reflog at all.
tagsAnnotated and lightweight, told apart.
worktrees · submodulesThe linked working trees, and the submodules with their status.
remotesThe remotes this repository knows about.
search_start · search_stopStart a filtered walk on its own thread; starting one cancels the one before.
external_tools_configWhich diff and merge tools are installed, and what git is configured to use.
recent_reposThe repositories the user has opened. Nothing scans the filesystem.

CommandDoes

stage_hunk · unstage_hunkBy hunk, through a generated patch.

History#

CommandDoes
resetSoft, mixed or hard — named by effect at the call site rather than by flag.
revert · cherry_pickSingle or over a selection.
integrateMerge, rebase or fast-forward as one verb with a mode, which is what the drag gesture on the graph produces.
rebase_ontoA branch onto another.
rebase_todo · rebase_previewThe generated plan, and the fold of it. Neither starts anything.
rebase_run · rebase_progressExecution on a worker, with progress read from git's state counters.
rebase_continue · rebase_skip · rebase_abortThe three ways out of a stopped rebase.
checkout · checkout_detachedThrough git switch for a branch, which only ever changes branch.
create_branch · rename_branch · delete_branchNames validated by git, not by a second implementation of check-ref-format.
create_tag · delete_tagFrom the graph's context menu.
tag_create · tag_delete · tag_retagFrom the Tags screen, which also rewrites an annotated message.
stash_push · stash_actionPush, and then pop / apply / drop as one action with a mode.

worktree_add · worktree_remove · worktree_lock · worktree_unlock · worktree_pruneThe linked working tree lifecycle.

Network#

CommandDoes
fetch · push · pullOn a worker, watched while they run. network_release tears one down.
clone_planWhere a URL and a folder say the clone will land, and everything wrong with that — computed as the user types, without the network.
clone_start · clone_releaseThe one spawn that does not wait. Cancelling removes only what the clone created.
check_updateWhether there is a newer Spagitty. A check, not an updater.

The farm

All of these are async commands, because they take locks that agent threads hold.

GroupCommands
Lifecycle farm_open, farm_close, farm_create, farm_configure, farm_start, farm_pause, farm_cancel
State farm_snapshot, farm_events, farm_stale, farm_task_detail, farm_transcript

Events#

EventCarries
graph-rowsA batch of commit rows, stamped with its walk's token. Rows carrying a stale token are dropped.
graph-doneThe walk reached the end.
search-rowsMatches, as the filtered walk finds them, with a query token.
search-doneThat query finished.
clone-progressGit's own progress, parsed. An unrecognised line is still shown.
clone-doneThe outcome, including a failure's message read from stderr.
network-progress · network-doneA fetch or push while it runs, and its result.
rebase-progress · rebase-doneRead from git's state counters rather than parsed from output.
repo-changedThe watcher saw something. Refs moving debounces into a re-read and a re-walk; a worktree change re-reads the counts only.
git-commandOne execution as shell.rs recorded it — argv, outcome, exit code, duration, with any URL userinfo already stripped.
farm-eventOne FarmEvent, internally tagged and timestamped. Sixteen variants on one channel, because the screen keeps one activity list and one ordering.

The FarmEvent variants#

FarmStatusChanged, TaskCreated, TaskStatusChanged, TaskAssigned, TaskProposed, AgentStarted, AgentOutput, AgentStopped, VerificationStarted, VerificationFinished, ReviewRequested, ReviewCompleted, MergeRequested, MergeCompleted, WorkspaceChanged, Failed.
