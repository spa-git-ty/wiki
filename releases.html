Release history

Every version of Spagitty and what shipped in it, newest first. The full text is in CHANGELOG.md, which is also what gate 6 reads to produce a release's notes — a version's section becomes those notes verbatim.

Versioning

Semantic Versioning 2.0.0, and Spagitty is at 0.x: the surface is not yet stable, MINOR may break, PATCH stays backward-compatible. The format follows Keep a Changelog.

0.5.1 — 6 September 2026#

A reliability pass over the farm's edges, plus a development-mode styling fix.

  • Automatic merges got stricter. They now require passing checks and a successful independent review of the work actually committed, plus merge permission. Tasks keep their intended destination, and competing farm merges serialise rather than racing.
  • Verification output is drained continuously with bounded retention, and stopping a check or reaching its deadline terminates its whole process tree.
  • One completion watcher per run, review runs included, so a late result stays attached to the attempt that produced it.
  • Running agents and planners stay cancellable while background threads wait on them; Windows agent descendants are contained in a job before execution starts.
  • Development window sizing stays intact when a component stylesheet request arrives before its JavaScript.
  • Frontend routes are measured in coverage, and descendant termination is checked on all three platforms before a release.

0.5.0 — 5 September 2026#

The farm could run a plan but there was almost no way to watch it run. This is that release: a ring rather than a count, a chip for every working agent, a log you can read and filter, a queue that says why a task is waiting, and a task too big for one agent that can be cut into smaller ones.

Added#

  • The Farm screen is worth watching. 3 / 7 done becomes a ring — finished fills it, running is a brighter arc at its leading edge, blocked colours the rest — so a farm that is working looks different from one that stopped at the same count. One chip per working agent says who is on what and for how long.
  • A run that has gone quiet says so. After six minutes without a word the chip and the row say how long it has been silent and the pulse stops. Nothing is stopped for you.
  • Agents earn their badges from the farm. A task taken all the way to Done scores the agent that did it — whether the checks really passed, whether the reviewer approved, how many times it was sent back.
  • Every task says who asked for it. Your own tasks stay unmarked; anything an agent asked for carries one quiet mark, and its panel says which agent and why.
  • A task that is too big can be broken down. The subtasks arrive as a proposed plan under it, and the task becomes a heading that finishes when they do. A plan may hold 24 tasks; a farm may run 8 agents at once; the attempt limit became a setting.
  • A proposed plan is accepted in one action — a band with a checkbox per task, rather than opening each one.
  • A queued task says why it is not running, in the scheduler's own words.
  • The farm's log is a drawer you can read, with Activity and Transcript tabs, following, and Hold.
  • A little motion, where it says something — and nothing at all for a reader who has asked for reduced motion.

Changed#

  • A long session stops growing. The run history is bounded now; transcripts were always on disk and the drawer can read a task's whole log back from one.
  • Every farm event carries the time it happened, which is what makes a log a log.
  • Watching a farm costs almost nothing. The refresh no longer runs git worktree list and re-parses the whole activity log on the thread that paints the window.

0.4.1-alpha — 3 September 2026#

A pass over the palettes and the rail.

  • Four more palette families — Nord, Rosé Pine, Solarized and Everforest, each in light and dark, bringing the set to eight families and sixteen palettes.
  • Every theme now accents in its own hue. They all wore the brand amber, which put one colour on seven palettes built around a different one. A test now fails if two families ever share an accent.
  • The Farm is the rail's first screen, and the Graph follows it. The Graph still owns /.
  • Open repository leaves the rail once a repository is open. It was a filled accent button above every screen offering to replace the repository you were working in.
  • The repository's state moved from the rail's foot to the status strip — one line, in two groups, rather than four stacked lines duplicating the rail's own badges.
  • The Farm's first screen is a starter page, not an empty state: what a farm is, the loop in four steps, a goal field, and three readiness rows.

0.4.0-alpha — 3 September 2026#

The agent farm.

  • The agent farm. Spagitty runs and shepherds coding agents instead of only reading what they did. A new crates/spagitty-farm is the control plane and nothing else — every git operation still goes through spagitty-core. Inside it: the domain model, one adapter per provider, a branch and worktree per task with path-level lease locks, a deterministic verifier, a peer-review router, a dependency-DAG scheduler, and local persistence.
  • The first release to carry its pre-release suffix in the manifest.

0.3.0 — 2 September 2026#

Ten features, and four defects found on the way.

Added#

  • Worktrees management — view, add, switch, lock, unlock, remove and prune linked working trees.
  • File history and interactive blame — screen 1O, with rename following and a line-by-line gutter.
  • Diff syntax highlighting — grammar-based, mapped onto the theme's own palette tokens.
  • Image and binary diffs — side-by-side, swipe and onion-skin comparison; size deltas for binaries.
  • Diff content search — search inside added and removed patch lines.
  • Submodules management — status, recursive init and update, sync, deinit.
  • External diff and merge tools — discovery and launch, through git's own configuration keys.
  • Multi-identity profiles — named author identities, applied locally or globally.
  • Extended forge integration and in-app PR creation — GitLab and Bitbucket Cloud alongside GitHub.
  • Pull request lifecycle actions — merge, close, reopen and mark ready.
  • The delight layer, and God mode to drive it by hand.

Fixed#

  • The Accounts chip in Settings opened the License section — one chip with no branch, hidden by a catch-all.
  • Every <select> in the application was drawn by the operating system.
  • The External Tools section was themed against tokens that do not exist, so every palette but one fell through to a hard-coded fallback.
  • The Open repository button pushed its label to the far edge.

0.2.0 — 30 August 2026#

  • The PR review workspace. A full-window view with the description rendered, a collapsible pane of files and commits, an interactive diff with inline comment threads, replies and resolution, and drafts persisted locally.
  • Spagitty, with a face: the brand. The application identity became the mark, the wordmark and the palette.
  • A brand guide, an interactive showcase, and UI identity integration.
  • The frontend toolchain moved to Bun.

0.1.0 — 29 August 2026#

The first release. Everything below is new, so it is one Added section rather than a pretence that anything changed.

  • The graph — commit history as a lane graph with author portraits, branch chips carrying divergence, square lane turns, lane compression, and a detail panel that can be put away. Search, reflog and tags each got a screen of their own.
  • Working copy — stage, unstage, commit (with signing), discard, and a diff screen with split and unified views.
  • Branches — a sortable, resizable table with two-sided divergence bars; create, delete, rename; checkout from the toolbar.
  • Stash — list, pop, apply, drop, and browsing an entry file by file.
  • Rebase — interactive planning and execution, and a conflicts screen that resolves and writes.
  • Remotes — fetch, push and pull; clone; remotes management in Settings.
  • Pull requests — read from GitHub, split into what needs you and what is waiting on others.
  • The chrome — repository tabs, a grouped toolbar, a collapsible nav rail, a status strip, themes, frosted-glass menus and dialogs, and the git command behind each action shown as it runs.
  • Update check, and the release lane — three lanes, all three platforms, notes from the changelog.

Two earlier preview builds were cut before the changelog existed. They remain published as pre-releases and are superseded by 0.1.0 — not withdrawn, only preceded.

Milestones in the pipeline#

DateWhat
26 August 2026 Gates 1 to 4 ran for the first time, on the first pull request. Nine and a half minutes, all four green. The workflows had landed with the code they gate and then waited for a remote to run on; that wait turned out to have been right.
28 August 2026 Gate 5 built all three platforms green on the first merge into main. Gate 6 failed on the same run — the runner had no git identity, so git tag -a refused with fatal: empty ident name. Nothing was tagged and nothing was published: a halt, not a broken release. The fix set the bot identity and moved the notes off generated text and onto the changelog.
